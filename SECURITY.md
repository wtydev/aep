# Security model (AEP v0.1)

This document states what the protocol and the reference implementation protect against, how each
claim is tested, and what is not protected. A claim without a test is listed under limitations.

## Threat model

- **Clients are untrusted.** An AI agent may send malformed, oversized, replayed, out-of-scope or
  hostile requests. The host is the sole authority on project state.
- **Project files are data, never code.** A project document contains no executable content. AEP
  defines no operation, field or extension point that makes a host execute Python, JavaScript,
  shell or plugin code supplied through a project or request. Device parameters are opaque values.
- **Transports are local.** v0.1 bindings (directory, stdio, in-memory) assume the OS user account is
  the trust boundary. There is no network binding and therefore no TLS in v0.1.

and writes them to files with mode 0600.

## Limitations (not protected in v0.1)

- **Same-user processes.** Any process running as the same OS user can read credential files and the
  directory binding. Use OS accounts or containers to separate agents from the editor.
- **No durability.** The reference host keeps ledger, history, proposals and assets in memory. After
  a restart, retried requests can execute again. A production host must persist the ledger before
  it reports effects.
- **Directory client replay.** `DirectoryClientTransport` returns an existing `results/<id>.json`
  for a reused id without asking the host, so it cannot detect `id_conflict` for a reused id with a
  different body. Clients must generate fresh ids (the SDK does).
- **No rate limiting or quota per session** beyond the per-request limits.
- **Render and generation executors** in the reference host are test doubles. Real executors
  (audio renderers, generative models) are outside AEP; hosts must sandbox them. AEP only passes
  them validated parameters.
- **Asset content is not inspected** beyond size, SHA-256 and a PCM WAV header sniff. Hosts that decode
  media must treat files as untrusted input.
- **No signing or provenance verification.** `provenance` on assets is descriptive and unverified.
- **No security audit** has been performed.

## Reporting

Report vulnerabilities privately to the maintainers. Do not open a public issue.
